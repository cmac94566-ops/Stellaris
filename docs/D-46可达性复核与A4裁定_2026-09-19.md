1. zcode 报告的**主体结论成立**：勘测、建造船建前哨、船坞造舰队列三条链路在脚本层**确不可达**。

   本处属"检索范围未覆盖 events/"的第二次同型失误。

   是**明确的"凭空落成"形态**（`every_planet_within_border` 内直接对行星落殖民地，全程无殖民船）

### 2.1 关键补充证据（zcode 报告未含）

- `create_colony` 作为**独立效果**存在（`effects.log:381`，"Creates a colony on the scoped planet"），
  与 `create_ship` 的同名参数（`:356`，`create_colony = yes/no`，"only when ship_size is marked to carry a colony"）**是两个不同东西**，不要混谈。
  独立效果形态（凭空落成）实例：`02_machine_age_effects.txt:2515`
  ```txt
  every_planet_within_border = {
      limit = { exists = sector  sector = { has_sector_type = core_sector }  is_colonizable = yes }
      create_colony = { owner = root  species = root.species }
  }
  ```
- `start_colony` 唯一用例的 scope 说明是 **Fleet scope**（事件头注释 `#This = Fleet scope`），
  而 `effects.log:1317` 文档写"scoped planet" —— **文档与用例 scope 表述不一致**。这正是不该拿"零用例"当结论的原因：
  该效果的 scope 语义本身就需要实验确认。

## 3. 公理 A4 裁定（**b′ 混合**，2026-09-19 21:0x）

**A4 原文**：「所有操作流程尽量贴近真实人手操作，不要凭空生成」→ 澄清「指的是游戏内 ai 的操作，
比如**调查星系再建立哨站**」。

用户举的例子包含**两个要素**：① 顺序（先调查、后建站）；② 对象是"AI 的操作"。
所以纯 b（只承认②）会丢掉①，纯 a（只保①）会在脚本层卡死扩张。**裁定如下**：

- **R-A4-1（采纳 b 的解释）**：`create_starbase` / `create_ship` 这类**引擎效果直建**，
  在"AI 内部建模"语义下**不构成凭空生成** —— 原版 AI 的哨站建造同样是效果驱动。
  ⇒ 从 D-46 的违规清单中**降级**为"合规但需顺序门"。
- **R-A4-2（强制 a 的顺序门，可观测）**：任何 `create_starbase` **必须有前置的真实动作**：
  用 `queue_actions`（fleet scope）把**科研船 `move_to` 目标星系**，`wait` 至抵达
  （**已取证 `move_to`/`wait` 是 queue_actions 的受支持动作**，见 §2 #5）。
  顺序的可观测锚点 = 同一星系"科研船抵达日志 → 建站动作日志"的**时序对**。**禁止无前置动作的裸建站**。
- **R-A4-3（唯一豁免步骤，必须显式留痕）**：`set_surveyed` 是**唯一的代打步骤**（引擎无勘测指令，见 §2 #1）。
  ⇒ 允许保留，但**必须在代码内以 `# A4-豁免：引擎无脚本勘测通道` 注释标注**，
  并在日志打出**专用标签**（建议 `【勘测-代打】`），使其在验收时**不可能被误认为真实勘测**。
  **禁止**把代打日志写成像真实勘测一样（铁律 20：不得写"只打日志不做事"或"粉饰身份"的日志）。
- **R-A4-4（殖民链路）**：`create_colony` / `start_colony` **在受控实验出结论前不得上线**。
  实验目标只有一个：**它是否消费运输载具**（消费 ⇒ 合规；不消费 ⇒ 凭空，禁）。
- **R-A4-5（新增审计点）**：`create_colony`（凭空形态）须与 `create_starbase` **同级登记**，
  不得因为报告的分组方式（"殖民船殖民=存疑"）而被漏掉。

## 4. 验收标准（AC）

| AC | 判据 | 通过条件 |
|---|---|---|
| **AC-1** | 顺序门可观测 | 任一次 `create_starbase` 之前，同一星系存在**科研船 `move_to` 动作记录**；裸建站 0 次 |
| **AC-2** | 代打留痕 | `set_surveyed` 调用点**每处**带 A4-豁免注释；日志含 `【勘测-代打】` 且**与真实勘测标签不同名** |
| **AC-3** | 凭空点归零 | `create_colony` 独立效果调用 **0 处**（改造前为 1 处，`autonomy.txt:4222`） |
| **AC-4** | 实验前置 | 殖民链路上线前，必须有受控实验报告回答"是否消费载具"；**未实验即上线 = 不通过** |
| **AC-5** | 无回退 | 改造后 `error.log` 涉 `queue_actions` / `move_to` 报错 **0 条**；`【相位】` 结构无明显退化 |

> **判据口径提醒**：AC-1 判"动作记录存在"，不判"勘测完成" —— 因为引擎不提供勘测完成的可读信号。
> 不得把 `set_surveyed` 的效果当作 AC-1 的证据（否则顺序门退化为自证循环）。
