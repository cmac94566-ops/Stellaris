## 1. 结论（先行）

**S-13 的「选择」分支在正常开局下结构性不可达；而「推进」分支在无启动通道时是纯无效累积。**
三句话：

1. **原版 `game_start.60` 在开局事件里已经替每个帝国选好了议程**（非格式塔 → `agenda_infinite_opportunities`，
   并预置 **6000 / 7000** 进度）⇒ `has_agenda_selected = no` **从第一个 tick 起即为假**。
   我方判据 `limit = { has_agenda_selected = no }` 因此**永远不成立**，`set_council_agenda` 链**永不执行**。
2. **第二档 `agenda_unlock_slot`（本策略的唯一实质收益：+1 内阁席位）在全部 146 档镜像里 0 次命中**
   ⇒ 该档**从未被选中过**（全库级否定性结论，检索范围见 §3.1）。
3. **我方推进通道（`add_council_agenda_progress_percent = 0.1`）在议程「从未启动」的前提下
   已无意义地堆到 459,642（阈值 7,000 的 65.7 倍）**，且引擎侧的启动效果
   （`agenda_infinite_opportunities_finish`）**在本局从未出现**（同存档另有 7 国持有该修饰符）。

**唯一的好消息（也是本轮的正面产出）**：启动议程**可以脚本化** —— 原版存在
`finish_council_agenda = yes`（`common/relics/grand_archive_relics.txt:556`，唯一先例）。
即：**"启动需要 UI 点击" 这一前提被我方推翻**，S-13 有可落地的完整闭环。

## 2. 完整因果链（一句话版）

```
原版 game_start.60 开局选议程 + 预置 6000/7000
        └─▶ has_agenda_selected 恒为 yes
              └─▶ 我方「选择」分支恒不执行（om_agenda_1_done/2_done/exhausted 全库 0）
                    └─▶ 档 2（+1 内阁席位）结构性不可达
        └─▶ 议程就绪后无人启动（脚本无启动调用、玩家不操作）
              ├─▶ 启动效果 agenda_*_finish 从未生效（本局 0 次）
              └─▶ 议程永占槽位 ⇒ 槽位永不空出 ⇒ 上面那条链永远没有第二次机会
        └─▶ 我方推进通道 700/月 → 17 年堆到 459,642（65.7× 阈值）
              └─▶ 净收益 = 0（启动无门），净代价 = 每月一次无效 effect 求值
```
