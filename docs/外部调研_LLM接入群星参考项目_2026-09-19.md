## 二、两个重点项目的架构与可采纳点

### 1. IAG（imperial-auto-governor）——同赛道最强参照（确证，读 README 全文）

**架构**（与我们有本质差异，值得看清）：
- 它**不走 mod 内 scripted_effects 改游戏**——核心链路是「存档解析 → 规则引擎生成候选 → 模型只从候选中决策 → 确定性校验 → Execution Broker」→ 执行走两条路：
  - `session_proxy`：**联机 UDP 协议拦截**（发现真实流量四元组、插入已验证完整命令、维护 ACK/actor serial 映射，需管理员权限）；
  - `carrier_click`：载体 mod 让载体星球产生**合法命令**，Host Bridge 在入房主前受约束改写。
- 已逆出 **Stellaris 4.4.6 动作码库**（与我们同版本！）：28 个可验收动作，含**科研船/工程船自动化（探索、勘探、特殊项目）**、**工程船建恒星基地**、**订购殖民船并殖民**、恒星基地升级/模块/建筑、舰船设计 fb2d 等。

**对我们最有价值的五点**：

| # | IAG 的做法 | 对我们的意义 |
|---|---|---|
| ① | 「核心不是 Clausewitz Mod 直接修改玩家殖民地」——**连最较真的真实链路派，也承认 mod 脚本层没有真实建造/勘测链路**，只能绕到协议层或载体命令 | **直接佐证我们 A4 裁定 b′**：科研船勘测/建造船/殖民船在**脚本层**不可达是真边界（我方 067 查证 + IAG 旁证）；未来若真要走「真实链路」，路线图 = 协议层，且它的 4.4.6 动作码证据可直接参考（GPL-3.0，内部参考合规） |
| ② | **候选白名单**：「规则引擎生成游戏当前允许的候选，模型只从候选中决策」；舰船设计「不让模型拼二进制」，确定性层管组件/科技/功率 | 与我们 S-18 规则集同构（LLM 离线产出、引擎执行）。A4 实施可引用此模式：D-46 的顺序门本质就是「候选 + 门」，已在做 |
| ③ | **「执行账本依据网络证据或后续存档确认结果，而不是相信模型自述」** | 与我们「自报完成 ≠ 事实完成」铁律完全同源——业界独立演进到了同一条纪律，可引为佐证 |
| ④ | **计划驱动**：Plan 节点在容差内**不调模型**（本地确定性续跑），超差才失效相关节点回模型；每 12 游戏月联合复盘只读压缩摘要 | **S-20 复盘频率设计的直接参考**——我们当前「LLM 月度产出规则 + 引擎求值」已同构，下一步降低调模型成本可借鉴「容差内免模型」 |
| ⑤ | 跨 Application **资源账本按存档哈希预留支出**，防多 Agent 重复花同一份旧库存 | 我们的多相位并行执行预算（A2）可借鉴「按存档 revision 预留」防并发超支 |

### 2. stellaris-companion —— M2-5 的现成同构参考（确证，读 README 全文）

## 三、与本项目架构的对照结论

| 维度 | 本项目 | IAG | companion |
|---|---|---|---|
| 游戏内执行 | **mod scripted_effects**（引擎内求值，无外部通道） | 协议拦截/载体命令（引擎外注入） | 不执行 |
| LLM 角色 | 离线产出**规则集**，引擎每 tick 求值 | 在线决策但**只从白名单候选选** | 纯咨询（消费 briefing） |
| 状态获取 | 自读存档（zipfile+正则）+ game.log | 存档解析 + 网络回包证据 | Rust/jomini 解析 + SQLite 快照 diff |
| 防幻觉 | 候选门（A4/顺序门）+ 台账核销 | 候选白名单 + 确定性校验 + 不信自述 | 不操作故低风险 |
| 调模型频率 | 规则集换版时（低频） | 容差内免模型（更低频） | 每问一次 |

**总评**：我们的「LLM 离线产出规则、引擎高频求值」路线与 IAG 的「候选白名单 + 容差内免模型」是**同一思想的两种实现**，且我们在「执行在引擎内」这点上比 IAG 的协议注入**更稳**（无封号/联机同步风险、无版本动作码脆弱性——IAG 自己都为 4.4.6 动作码写了兼容性验收套件）。IAG 真正领先的是**舰船/舰队/殖民的动作覆盖广度**——那靠的是协议层，属不同技术路线，短期不追。
