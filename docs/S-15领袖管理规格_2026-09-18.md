### 1.2 残留缺陷（阻断级，静态即可判）

#### 🔴 缺陷 1：tick 挂载点仍在调用**未定义/未使用**的效果（需核实是否已清理）

- `:2484` 挂载 `overmind_autonomy_manage_leaders = yes`；

  与实际实现一致即可，属文档一致性问题，非阻断。

#### 🔴 缺陷 2：**舰队判空的写法虽正确，但 `leader` 属性的 scope 断言缺失**

```txt
any_owned_fleet = {
    is_mobile = yes
    leader = { always = no }   # ← 舰队无领袖
}
```

**取证结论：写法合法，但语义可疑。**
- `exists = leader` 是原版权威判空式（本机 `caravaneer_scripted_effects.txt:212`
  `NOT = { exists = leader }`，`is_ship_class = shipclass_science_ship` 同层）✅
- 但 `leader = { always = no }` 的语义是「**若舰队有领袖，则该领袖满足 `always = no`**」——
  当舰队**无领袖**时，该块是否判真，取决于引擎对"不存在 scope 对象"的处理。
  **原版零先例**（本机全库 `leader = { always` **零命中**）。
- ⇒ **风险**：若引擎对空 scope 返回 **false**，则该 `limit` **永假** ⇒ 整个补领袖逻辑**静默不触发**
  —— 与 D-34「traditions 静默不推进」是**同一类失效模式**（门在、却不生效）。
- **修正建议（照抄原版权威式）**：
  ```txt
  any_owned_fleet = {
      is_mobile = yes
      NOT = { exists = leader }   # ← 原版权威判空式（caravaneer:212 先例）
  }
  ```
  同理 `random_owned_fleet` 内的 `limit` 也应改用 `NOT = { exists = leader }`。

#### 🔴 缺陷 3：**`create_leader` 的参数集需核对 `species` 在 country scope 的可用性**

```txt
create_leader = {
    class = commander
    name = random
    species = owner_main_species   # ← 待核查
    skill = 3
    randomize_traits = yes
}
```

- **scope 问题**：`create_leader` 在 **country scope**（本效果体由 tick 直接调用 ⇒ 效果内 root = country）✅；
- 但 `owner_main_species` 是 **`owner` 作用域下的成员**，在 **country scope 直接写 `owner_main_species`
  属可疑**——本机原版 `create_leader` 语料中，`species` 参数应以 **`root.species`/`owner_main_species`
  的合法上下文**给出，**请实机验证**（`error.log` 有无 `Invalid` 行）；
- **替代写法**：`species = root.species`（country 的 `species` 属性）或直接省略 `species` 参数
  （原版多数 `create_leader` 调用并不指定 species）。
- **我方判定**：3 处 `create_leader` 调用点均应逐参数比对原版范例
  （本机 `common/scripted_effects/00_scripted_effects.txt` 内 `create_leader` 段），**不猜**。

### 1.3 其他观察

- **效果层级**：本效果由 tick（第 4 层）调用 ⇒ 效果体第 5 层，内嵌 `if/limit/any_owned_fleet` 第 6 层，
  **未触及第 7 层硬上限** ✅（对照 `build_ship` 包一层即超限的先例，此处层级设计正确）。

- **`is_mobile = yes`**：本机 12 处先例，合法 ✅。用途为排除星港/空间站，与 `build_ship` 既有经验一致 ✅。

## §2 规格（v3 —— 建议直接采纳）

### 2.1 设计原则

**不记账、实时查；每层只做一件事；失败要留证（日志）不静默。**

### 2.2 能力定义（S-15 v3 最小可用集）

本版**只做 2 项**（其余依赖引擎自动分配，4.4 已移除失业机制，脚本层无解雇/调岗能力）：

| 能力 | 触发条件 | 动作 | 日志锚点 |
|---|---|---|---|
| **A. 舰队指挥链补齐** | 我方存在 `is_mobile = yes` 且 `NOT = { exists = leader }` 的舰队 | 创建 1 名 `commander`，并 `assign_leader` 给该舰队 | `OVERMIND: 【领袖】 创建指挥官（skill 3）` |
| **B. 保有量下限** | 同 A（由 A 的结构天然覆盖：无领袖舰队存在 ⇒ 补） | 每次 tick **至多补 1 名**（避免一次爆量） | `OVERMIND: 【领袖】 指挥官已就任 舰队<FLEET> ` |

**不做**（明确排除，防止范围蔓延）：
- ❌ 解雇 / 调岗（`dismiss_leader` 语义存疑、`fire_leader` 零命中，见 BACKLOG S-15 行）；
- ❌ 特质刷新 / 内阁换人（`set_council_position` 另案，V-9 再议）；
- ❌ 科学家/官员的分配（社区共识：指挥官**绝不放研究世界**，伤专家产出 ⇒ 本版只碰舰队）。

### 2.3 伪代码（供 zcode 实现，非最终代码）

```txt

    if = {

            any_owned_fleet = {
                is_mobile = yes
                NOT = { exists = leader }        # 原版权威判空式
            }

        overmind_autonomy_create_commander = yes
        random_owned_fleet = {
            limit = {
                is_mobile = yes
                NOT = { exists = leader }
            }
            assign_leader = last_created_leader   # fleet scope 内的正确形态
            log = "OVERMIND: 【领袖】 指挥官已就任该舰队"
        }
    }
}
```

| # | 验收项 | 判据（可机械验证） | 通道 |
|---|---|---|---|
| AC-1 | 无 `Wrong scope` / `Invalid effect` | 重启后 `error.log` 中涉 `overmind_autonomy.txt` 的 `Wrong scope` = **0**、`Invalid effect` = **0** | 日志 |
