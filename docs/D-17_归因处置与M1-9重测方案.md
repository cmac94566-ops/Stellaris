⇒ **本轮 2222→2227 的数据同时否定 D-7 验证与 fleet 修复验证，两者都必须重开一局。**

**E2（确证）开关用错了对象。**

**E3（确证）存档里查不到任何 `human_ai` 痕迹。**

**E4（确证）「有 `ai={}` 块」不能当接管证据。**

⇒ 之前那条「`ai=` 块活跃」的证据线索**作废**；同时也说明**存档通道无法回答"原版 AI 是否在跑"**。

**E5（确证）原版 AI 接管会让整个自治层静默全停 —— 比 §1 预估的严重。**
- 本族**全部** 7 个事件（300/301/302/303/310/320/321）的 `trigger` 都带 `is_ai = no`。
- `human_ai` 一旦生效，玩家国家被判定为 AI，连锁后果：
  * **300 停止触发 → 自治心跳静默全停**（不是"减慢"，是一个动作都不做）；
  * 法令面板两条法令同时消失（`potential` 带 `is_ai = no`）→ D-18；
  * 连 `321`（关闭事件）也带门，但因 edict 直接调用 `overmind_autonomy_disengage`
    scripted_effect，F2 修掉 `potential` 后开关路径仍然可达。
- **反证（对 D-17 本身）**：本轮 20:31–21:37 期间模组持续打日志（95 条 OVERMIND，
  含每年一次的年度外交），而 300 要触发就必须 `is_ai = no`。
  ⇒ **在该时间窗内 `human_ai` 并未生效**（或未改变 `is_ai` 判定）。
  结合 E3/E4，"human_ai 到底何时生效、是否生效过"存档无法回答 ——
  这恰好证明 F1 的必要性：归因状态必须由日志当场给出，不能靠事后考古。
- **验证方法（不用改任何东西）**：现在打开帝国 → 法令（Edicts）面板，看有没有
  「主脑自治」条目，**同时看日志窗口还有没有新的 OVERMIND 行**。
  两样都在 = 未接管；两样都消失 = 接管了。

## 3. 处置方案（三项，待签字）

### F1 · 归因守卫日志（核心）
把「有没有第二个行动主体」从**不可观测**变成**日志第一行就写死**。

在 `overmind_autonomy_tick` 开头（相位分发之前）插入：

```
if = {
    limit = { is_ai = yes }
    log = "OVERMIND: 【告警】 本国当前被判定为 AI 控制 —— 原版 AI 可能在接管，本轮指标不可归因"
}
```

- 成本：1 层嵌套（`if` + `limit` 免费，`log` 不额外计层），不触碰 5 层上限。
- 收益：日志窗口里**每次跳月份**都会刷这条；只要它出现过一次，本轮所有指标自动失去验收资格。**再也不用靠事后考古存档**。
- 配套：`tools/overmind_log_window.py` 增加 `【告警】` 高亮（品红加粗），优先级排在 `【异常】` 之下、`【相位 ` 之上。

### F2 · 让关闭开关永远在位（对应新增 D-18）
`overmind_autonomy_off.potential` 去掉 `is_ai = no`，只保留 `has_country_flag = overmind_autonomy`。

- 理由：`on` 保持 `is_ai = no`（防止原版 AI 自己打开我们的引擎），但 `off` 必须是**无条件可达**的紧急出口。
- 代价：AI 国家面板里可能多出这条法令；用已有的 `ai_weight = { weight = 0 }` 兜住（该文件头已论证 `ai_weight` 才是实装键名）。
- 风险：低。不改变任何 effect 语义，只放宽一个 `potential` 条件。

### F3' · M1-9 重测协议（按三席评审整改后修订，原 F3 作废）

必须**全部**满足，结果才进验收：

1. **重开一局**（或重启游戏进程）—— 不重启就还是旧代码，E1 会原样复现。
   `om_ships_built` 在旧代码存档里**不存在**，探针显示"（无记录）"即可当作
   "还在跑旧代码"的又一确证。
2. **不要**在控制台敲 `human_ai`；开关一律走**法令面板**。
   开局**之前**也要确认没开 human_ai —— 这是 304 守卫唯一的残余盲区
   （从未 engage 则无告警，此时日志里零 OVERMIND 行，本身即证据）。
3. 开局后在**日志窗口**连续确认三件事：
   - 看得到 `OVERMIND: 【相位 N/8] …`（证明 D-7 上线）；
   - **每月一条 `OVERMIND: 【归因OK】 …`**（R-1：归因干净由存在性证明，
     自治层在线却整月零心跳 = 异常信号）；
   - **一条 `【告警】` 都没有**。
4. **采样策略（R-4 修订，✅ 已执行 2026-09-15）**：`settings.txt` 的 `autosave`
   已由 5 改为 **1** —— 高频样本既保住趋势所需的全部历史，又顺带消解 D-15 的
   年度采样混叠。12 年的等待时间用现成的 **303 验收加速器**解决：给玩家国家置
   `om_verify_boost`，事件自递归按天快进，等价于无人干预快跑（它本身
   `is_ai = no` 门控，不影响归因）。
5. 用 `scripts/overmind_metrics.py --trend <存档目录>` 出表；判定用
   **AC-4 v2**（D-13 决策 A）：① 终值不低于初值；② 无 ≥3 个连续采样点的
   持续下降段；③ 冻结标「注意」。`fleet_size` 之外还要看**探针的
   「建舰累计」`om_ships_built`**（R-2）—— 它是建舰行为的第二证据源，
   持续增长才证明军事相位真的在动手；`fleet_size` 冻结而 `om_ships_built`
   在涨时，CLI 会打出矛盾告警。
6. 指标定位已不依赖 `player` 字段（R-3）：即使 `play <id>` 切换过扮演对象，
   度量仍锁定带 `overmind_autonomy` flag 的帝国。
