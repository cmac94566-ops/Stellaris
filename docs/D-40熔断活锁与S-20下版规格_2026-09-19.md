### 1.5 次级缺陷 D-40b（**推断** · 读码所得，请 zcode 复核）

`change_variable = { ... om_lex_gain_pN_streak value = 1 }`（如 `:2618`）的 `limit`
**只判 `NOT = { om_lex_gain_pN >= 1 }`，没有同槽位门控**（对比同一块的 reset 写法
`if = { limit = { om_exec_1 value = 1 } ... }` —— 它是有门控的）。

⇒ **一个槽运行，会把 8 个相位的 streak 一起累加** ⇒ streak 实际是「全局无收益月数」而非「每相位无收益月数」，
与 A3 的「该相位没收益就停下」语义不符。
（本例中该分支从未执行，所以**尚未造成可观测影响**；但它会在 R1 修好后可观测地跑起来，**必须同批修**。）

### 1.6 为什么是 222（**推断** · 仅供 zcode 定位，不作结论）

222 是**最后一次** `else` 执行（规则集启用前/或某次短暂放行）时留下的**陈旧值**；
p3 = 1、p5 = 2 说明这两个相位在那一刻刚被 reset 过。
**待 zcode 用 `om_exec_*` / `om_bf_phase` 观测实证**——但**它不影响 D-40 的定性**：
关键是「20 年不变」这一事实本身。

## 2. 因果链（三段）

```
① 存量存档里 6 个相位的 streak ≥ 3（陈旧值，或早期真实无收益累积）
        ↓
② 求值器把规则 #1/#2/#3（acts 8/6/1）放进 3 个并行槽（求值**不看熔断态**，`:1412-1469`）
        ↓
③ 分发时三个槽**全部**撞熔断门 ⇒ 打 3 条熔断日志、**0 次执行**
        ↓
④ 熔断门的 else（唯一 streak 写入点）不执行 ⇒ streak 冻死 ⇒ 回到 ①（**活锁**）
        ↓
⑤ 相位 1/6/8 在 exec 集内 ⇒ 回填通道**认为它们"已被覆盖"**、不补跑
        ↓
⑥ 实际行为 = 每月固定跑 5 个相位（2/3/4/5/7）+ 3 条噪音日志；
   **相位 1 RELIEF / 6 MILITARY / 8 WAR 永久停摆**
```

**代价**：`RELIEF`（赤字救火）· `MILITARY`（建舰/军力）· `WAR`（战时管理 S-8）三条链路**全部断开**；
且 117 行/局的熔断噪音淹没有效日志。**净效果比原 8 槽轮转更差**（轮转至少 8 个相位轮流跑）。

## 3. 对既有验收的订正（**我方自查，与 zcode 无关**）

`WDMSG-070` / `WDMSG-071` 把 P0 判为「**相位覆盖 8/8**」，依据是
「相位入口 5/8 + 3 规则槽 = 覆盖 8/8」。

**该口径不成立**：「被规则槽指向」≠「执行」。3 个规则槽产出的是**熔断日志**。

| 判据 | 上一轮结论 | 订正后（只计执行） |
|---|---|---|
| 相位覆盖 | 8/8 ✅ | **5/8**（相位 1/6/8 执行 0 次） |
| 判据方向改正（`1419455`） | 生效 | ✅ 仍成立（去重日志可读、`同相位` 与 `执行集已满` 不再混用） |
| 回填轮转（`1419455`） | 生效 | ✅ 确实生效（195 次）—— **但它是当前唯一有效通道** |
| 活锁修复（`702b9a2`） | 生效 | ✅ 回填区活锁确已解；**主派发区活锁仍在（= 本件 D-40）** |

⇒ **P0 改判「部分通过」**。原始目标「规则集 → 执行」这条主链**仍不通**。
**新口径（强制）**：覆盖检查一律**只数 `【相位 N/8】` 入口日志**，并**同时报「回填占比」** ——
回填占比 = 回填次数 /（主通道执行 + 回填执行）；**回填占比 100% 即判「主通道失效」**。

## 4. S-20 下版规格（熔断机制改造）

> 设计总纲：**A3 的语义是「暂时跳过」，不是「永久禁用」**（无解除机制的熔断 = 披着节流外衣的静默死锁）。

### R0 存量自愈（**前置，必须有**）

**问题**：streak 是**存档变量**，修代码不改存档 ⇒ 续档局仍带着 222 的死锁进来。
**规格**：`engage` / 年度 `era_sync` 段加一次性自愈 —— 若某相位 `streak >= 阈值` **且**
`om_lex_probe_pN`（距上次尝试月数）缺失或 ≥ 探测周期 ⇒ **强制归零**（或首次尝试时必经一次探测）。
**判据**：重启后**首个 tick** 内，8 个 streak 不得再出现「≥ 阈值且 20 年不变」的组合。

### R1 streak 记账按槽位门控（**修 D-40b**）

把 `:2617-2632` / `:2700-2715` / `:2783-2798` 三块的「reset + 累加」合并到**同槽位门**下：

```
if = { limit = { check_variable = { which = om_exec_1 value = N } }        # 只对该槽真跑过的相位记账
    if   = { limit = { check_variable = { which = om_lex_gain_pN value >= 1 } } set_variable = { ... streak = 0 } }
    else = { change_variable = { ... streak = 1 } }
}
```

**注意 5 层预算**：`tick(1) → if(2) → else(3) → if/else(4)` —— 与现有 `run_slot` 调用点**同层**，
但需 `tests/test_bridge.py` 复核（S-18 曾因预算上提 `build_ship`）。
**判据**：给定「只有槽 1 运行、相位 4」，**仅** `gain_p1_streak` 变化。

### R2 熔断改「半开探测」（**核心**）

**规格**：熔断相位每 **`om_lex_probe_cycle`（默认 12 月）** 强制放行**一次**探测：

- 探测月：跳过熔断门，正常入集执行；探测月**不再额外记账**（避免污染 streak 语义），
  而是按探测结果 **有正收益 ⇒ 立即解除（streak = 0）**；**仍无收益 ⇒ streak 重置为 0 重新计时**。
- 实现最省路径：**熔断门改判「两个条件」** —— `streak >= 3` **且** `距上次尝试 < 探测周期`。
  「距上次尝试」用既有变量派生（如 `om_month` 与相位轮转指针），**不新建影子账本**（铁律 20）。
- **常量命名**：`om_lex_probe_cycle`，走 rev 通道与规则集同批下发（与 `om_parallel_max` 同族）。

**判据**：任一相位在**任意 12 月窗口**内至少被尝试 **1 次**。

### R3 槽位不浪费（求值期剔除熔断相位）

**问题**：现在熔断相位**仍占槽**（`evaluate` 不看熔断态，`:1412-1469`），占完再打日志跳过
⇒ 3 个槽全废，后续 9 条规则被「执行集已满」截断（`:1465` 等 12 处）。

**规格**：`overmind_autonomy_evaluate` 的入集门**追加「该相位非熔断态」** ⇒
熔断相位**不入集**，槽位让给**下一条规则**（优先级顺序自然下移）。
**连锁收益**：熔断相位不在 exec 集 ⇒ 若它**同时**被回填跳过（见 R4），就实现真正的「本月不做」。

**判据**：`【熔断】` 行数与 `【执行集已满】` 行数**同时下降**；`om_exec_1/2/3` 不再是每月固定的 8/6/1。

### R4 回填与熔断的边界（**必须写死**）

**现状**：回填判据 =「不在 exec 集里」⇒ 熔断相位在 exec 集内时**不被回填**（这正是 1/6/8 彻底停摆的直接原因）。
**规格**：回填判据改为「**该相位本月未被执行**」，且**显式排除熔断相位**
（否则熔断形同虚设 —— 跳过又被回填补上）。

- 回填**节流**：每月**至多补 1 个**未覆盖相位（按 `om_bf_phase` 指针递进），
  而非现在的「一次性补满 5 个」（195 次/局、5 相位/月）。
- **不得**让回填成为常态主通道：AC-6 设「回填占比 ≤ 50%」作为告警线。

**判据**：稳态下 `【回填】` ≤ 1 行/月。

### R5 降噪（`【熔断】` 日志）

**现状**：每槽每相位每月一条（117 行/局）。
**规格**：熔断日志改为 **① 状态跃迁时打一条**（本相位从「放行」变「熔断」或反之）；
**② 每 12 月打一条汇总**（本窗内熔断相位清单 + 空转月数）。
**判据**：`【熔断】` 行数 ≤ 状态跃迁次数 + 汇总行数（量级从 **≥100/局** 降到 **≤10/局**）。

### R6 保留既有解除通道

「条件组合变 / era 切换 / rev 递增」三条既有解除通道**保留**，R2 的探测是**第四条**（兜底、周期保证）。
