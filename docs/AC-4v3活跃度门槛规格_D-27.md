# AC-4 v3 规格 —— 活跃度门槛（D-27 修法）

> 触发：zcode MSG-027「D-27 活跃度门槛规格出稿后我随即实现」；用户 2026-09-17 实机观察。
> 性质：**验收判据修订**（v2 → v3）。规格归 WorkBuddy，实现归 zcode。
> 数据支撑：29 个回捞存档的**逐局** AC-4 实测（见 `docs/实机验证记录.md`）。

---

## 0. 为什么必须加（v2 的假阳性，已实证）

**AC-4 v2 只查「终值不降 + 无 ≥3 连续下降段」，而"完全停滞"同样满足这两条。**

实测反例（`_929703252`，2207–2211）：

| 指标 | 2207 → 2211 | 变化 |
|---|---|---|
| districts | 4 → 4 | 冻结 |
| buildings | 4 → 4 | 冻结 |
| zones | 3 → 3 | 冻结 |
| fleet_size | 15 → 15 | 冻结 |
| traditions | **0 → 0** | 冻结 |

v2 输出：五项全「注意」，**总判定未失败** —— 但这个帝国**没有任何一项在长**，
traditions 甚至始终为 0，是**彻底停摆**。

> ⇒ **"不下降" ≠ "在变强"**。AC-4 的语义是「主脑自治层**让帝国变强**」，
> 停摆即不达标。v3 补上这道门。

## 1. 新增两道门

### 门 1：活跃度（Activity Gate）—— **主判据，可判死**

| 项 | 定义 |
|---|---|
| 核心指标集 | `districts` / `buildings` / `zones` / `fleet_size` / `traditions` |
| 单项达标 | 窗口内**净增长 ≥ max(2, 初值 × 5%)** |
| 通过条件 | **至少 1 项**达标 |
| 失败处置 | 0 项达标 ⇒ **判「停滞 · 不通过」**（不再只是"注意"） |

**阈值校准（基于实测四局）**

| 局 | 窗口 | 实际增长 | 应有判定 |
|---|---|---|---|
| `3_377233607` | 2303–2307 | districts **+4** / buildings **+5** / zones **+1** ⇒ 3 项达标 | ✅ 通过 |
| `_-1527168959` | 2216–2220 | fleet **+25** / traditions **+1** ⇒ 2 项达标 | ✅ 通过 |
| `_929703252` | 2207–2211 | **0 项** | ❌ **停滞·不通过** |
| `_2063234607` | 2240–2242 | 全负（-13 / -24 / -13） | ❌ 不通过（v2 已拦） |

> 取 `max(2, 5%)` 的理由：下限 2 排除单点波动；相对值 5% 适配晚期大帝国
> （若一刀切卡 5%，`buildings 141→146`（+3.5%）会被误杀 —— 但该局 `districts 22→26`（+18%）达标，
> 结论不受影响；用 `max` 两者兼顾）。
> **"至少 1 项"是有意宽松**：只要有一项在长，说明自治层没瘫，不应判死。

### 门 2：效率（Efficiency Note）—— **只标注，不判死**

来自用户实机观察（能源 / 食物满仓溢出）：

| 项 | 定义 |
|---|---|
| 判据 | `energy` 或 `food` 在窗口内 **≥80% 的采样点**处于 **≥90% 存储上限** |
| 处置 | 标 **「⚠️ 效率：资源溢出」**，**不影响总判定** |

作用有二：① 报告里点名浪费（与 P3「冗余不等于囤积」呼应）；
② 充当 **D-29 满仓抑制门的效果验证口径** —— 抑制门生效后，该标注应消失。

## 2. 判定流程（v3 全流程）

```
① 按局分组（帝国 ID）
   ⚠️ 铁律：跨局不可混算 —— 已实证：29 存档混算得出"不通过"是错的
     （不同帝国规模相差数十倍，跨局跳变被误判为下降趋势）
② 样本门槛：窗口 < 5 年 ⇒ 只报「样本不足」，不给结论
③ v2 三条：终值不降 / 无 ≥3 连续下降段 / 冻结标注意
④ 门 1 活跃度：0 项实质增长 ⇒ 「停滞 · 不通过」
⑤ 门 2 效率：长期满仓 ⇒ 标注「⚠️ 效率」
⑥ 输出：总判定 ∈ { 通过 | 停滞·不通过 | 下降·不通过 | 样本不足 }（+ 可选效率标注）
```

---

## 3. 验收标准（守卫 6 条）

1. **停摆必判死**：注入"全指标冻结 5 年"序列 ⇒ 必须判「停滞·不通过」
   （注入"删掉活跃度门" ⇒ 守卫失败）。
2. **真实增长不误杀**：注入 `3_377233607` 实测序列 ⇒ 判**通过**。
3. **必须按局分组**：跨局混合输入 ⇒ 分**局**分别判定（注入"不分组" ⇒ 守卫失败）。
4. **样本不足要拦住**：窗口 < 5 年 ⇒ 输出「样本不足」而非任何结论。
5. **效率门只标注**：注入"长期满仓"序列 ⇒ 出现「⚠️ 效率」，但**总判定不变**。
6. **回归**：v2 既有行为（终值不降 / ≥3 连续下降段）不变，既有用例全绿。
