## 3. 动作覆盖度（现状 vs 目标）

> **度量口径说明**：本表用"mod 现役脚本里出现过的、且在动作清单内的名字"做分子，
> 动作清单各领域名字数做分母。该口径会把数据键（`name`、`icon`、`allow` 等）
> 一并算进去，所以它只是**粗略指数**，不是精确覆盖率。口径本身也应在 M2 里收紧。

| 领域 | M0 基线 | M1 现状 | 目标（M4 出口） |
|---|---|---|---|
| 经济与建造 | 22 / 531 (4.1%) | 24 / 531 (4.5%) | ≥ 60% 高频动作 |
| 战争与舰队 | 12 / 557 (2.2%) | 9 / 557 (1.6%) | ≥ 60% 高频动作 |
| 外交与情报 | 7 / 347 (2.0%) | 2 / 347 (0.6%) | ≥ 60% 高频动作 |
| 科技与传统 | 4 / 141 (2.8%) | 6 / 141 (4.3%) | ≥ 60% 高频动作 |
| 扩张与领土 | 0 / 163 (0.0%) | 0 / 163 (0.0%) | ≥ 60% 高频动作 |
| 领袖与内政 | 2 / 316 (0.6%) | 0 / 316 (0.0%) | ≥ 60% 高频动作 |
| 事件与脚本 | 19 / 316 (6.0%) | 12 / 316 (3.8%) | 工具类，不计入 |

**为什么战争 / 外交 / 领袖三项"下降"了**——这不是功能退化，而是口径变诚实：
三个数字里原先包含 M0 指令通道（`overmind_effects.txt` 等 4 个文件）的贡献，
而该通道**整体退役**并归档到 `_legacy/`，不再被游戏加载。
现役 mod 里剩下的名字才算数。M1 的实际新增（`create_army` / `create_starbase` /
`add_tradition` / `add_ascension_perk` 等）都是**真正会被执行的 effect**，
比旧通道里那些"写了但触发不了"的名字更有价值。

**结论（诚实版）**：执行层仍只是骨架，六个领域实际覆盖都在低个位数百分比。
M1 的交付标准是"**地基可信**"——每个新动作都必须过"语法确证 → 审计 → 实机"三步，
所以先扩相位（覆盖经济/科技/战争/飞升四条主线），而不是摊薄到六个领域。
其余按 M3（战斗深化）与 M4（内政外交深化）分批推进。
