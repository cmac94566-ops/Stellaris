# 游戏启停手册（Game Control Handbook）

> 目的：**让智能体自己完成「关游戏 → 开游戏 → 验证新代码生效」**，用户不再手动重启。
> 建立：2026-09-16（用户指令：「你要学怎么开游戏」「启动器里也要会操作」「开新对局也要会」）
> 工具：`tools/game_control.py`
> **等级标注**：🔵 确证（本机实测/文件证据） · 🟡 推断（社区说法或待验）

---

## 1. 三条关键事实（先讲，后面全靠它）

### 1.1 mod 由 `dlc_load.json` 决定，不由启动器 GUI 决定 🔵

- 路径：`Documents/Paradox Interactive/Stellaris/dlc_load.json`
- 它是**启动器写、游戏引擎读**的配置文件。当前已启用 7 个 mod，含 `mod/stellaris_overmind.mod`。
- **推论（重要）**：只要该文件正确，**直接运行 `stellaris.exe` 同样加载 mod** ——
  不必先让启动器 GUI 跑一遍。
- ⇒ 常规「重启验证」流程**可以完全绕开启动器**。
- 启动器仍然必要**只有一个场景**：要**改播放集**（启停 mod / 调 mod 顺序）时。
  此时它会写回 `dlc_load.json`。

### 1.2 启动参数 `-continuelastsave` = 启动后自动载入最新存档 🔵

- 证据：`stellaris.exe` 内字符串中，`-continuelastsave` 挂在 `frontendidler.cpp`
  （主菜单空转逻辑）之下。
- 效果：跳过主菜单与「继续游戏」点击，**直接进最新存档那一局**。
- 这解决了「启动后还要手点」的一半痛点。
- ⚠️ 它选的是 **mtime 最新**的 `.sav`。想让它进指定的局，就把那个存档的
  mtime 做成最新（见 §4 开新局）。

### 1.3 优雅关闭 = `taskkill <PID>`（**不带 `/F`**）🔵

- 不带 `/F` 会向窗口投递关闭消息（WM_CLOSE）→ 游戏**正常写退出存档后退出**。
- 带 `/F` 是强杀 —— **绝不使用**（可能丢掉最后一次存档）。
- 大帝国写存档可能耗时数十秒，脚本给了 120 秒等待窗口。

## 2. 三种启动方式对比

| 方式 | 命令 | mod 加载 | 能否带参数 | 适用 |
|---|---|---|---|---|
| **A. 直接跑 exe**（推荐） | `stellaris.exe -gdpr-compliant [-continuelastsave]` | ✅（读 dlc_load.json） | ✅ | 日常重启、验证新代码 |
| B. 启动器 GUI | `bootstrapper-v2.exe` → 面板里点 **PLAY** | ✅ | ❌ | **只改播放集/启停 mod 时** |
| C. Steam | `steam://rungameid/281990` | ✅ | 仅 Steam 启动项 | 手动场景 |

- 方式 A 需要 **Steam 客户端在运行**（DRM 校验）。已确认 `steam.exe` 常驻。
- 方式 B 的启动器路径：`AppData/Local/Programs/Paradox Interactive/launcher/bootstrapper-v2.exe`
  （同目录另有 `launcher-v2.2026.11.1/Paradox Launcher.exe`；游戏目录还有 `dowser.exe`，
  它接受 `--gameDir` 参数）。🟡 `--skip-launcher` 是社区说法（填 Steam 启动项），
  本机 exe 字符串**未命中**，故未采用。

## 3. 标准重启流程（最常用，一条命令）

```bash
python tools/game_control.py restart
```

等价于：
1. `stop` —— 优雅关闭（等游戏写退出存档）
2. `start --continue` —— 以 `-gdpr-compliant -continuelastsave` 启动，自动进最新存档

**这是"改完 mod 代码后让新代码生效"的标准动作**（Clausewitz 只在**进程启动时**加载 mod，
所以必须重启进程，改代码后热重载不存在）。

## 4. 开新对局（两种方案）

### 方案 1：开局存档复用（推荐，全自动）🔵

原理：`-continuelastsave` 认「最新存档」。于是——

1. 先准备一个**标准开局存档**（游戏内 2200.01.01，帝国/星系设置按你要的选好），
   比如存到 `D:/Stellaris_Saves/开局模板.sav`；
2. 以后每次要"新局"：
   ```bash
   python tools/game_control.py newgame --save "D:/Stellaris_Saves/开局模板.sav"
   ```
   脚本会把它**复制**到存档目录并置为最新 mtime，然后带 `-continuelastsave` 启动
   → 直接进新局。

- 优点：全自动、可重复、不碰原文件（只复制）。
- 前提：得先有那个模板存档（一次性，游戏内建）。

### 方案 2：启动器 GUI / 游戏内手动

- 启动器点 PLAY → 主菜单 → 新游戏 → 选帝国/星系 → 开始。
- **必须人工**（除非做 UI 自动化，见 §6 未实现项）。

### 方案 3：控制台 `reload_galaxy`

- 游戏内控制台命令，可重开一局。**本模组已退役控制台通道**（见 `_legacy/README.md`），
  不建议启用。

## 5. 验证新代码是否真的生效

```bash
python tools/game_control.py verify
```

检查项：

| 检查 | 通过标准 | 含义 |
|---|---|---|
| 【相位 N/8】计数 | > 0 | D-7 相位日志在线（新代码） |
| 【归因OK】计数 | 应 ≈ 相位计数 | R-1 归因心跳在线 |
| 【告警】计数 | **= 0** | 归因干净（F3' 前置条件） |
| `error.log` `Invalid relative power token` | = 0 | D-24 已修（需**新会话**复验） |
| `error.log` `Invalid macro` | 允许 4 条 | D-21 已知噪音，运行时宏正常 |

⚠️ **判断要点**：零相位标记 = 本局跑的是旧代码（或 mod 未加载）。

## 7. 安全约定（本工具自我约束）

- **永不删除、永不移动**用户存档 —— `newgame` 只做**复制**。
- **永不强杀**游戏（不主动用 `/F`）；超时只报告，交人工判断。
- 不改 `settings.txt` 等用户机配置（改前须单独确认）。
- `stop` 只在显式调用时执行；自动化流程里若发现游戏在跑，**不擅自关闭**。

## 8. 2026-09-16 实测修正（推翻第 1.1 节的乐观结论）

### 8.1 直接跑 exe 不可行（三次实测）

| 尝试 | 参数 | 环境变量 | 结果 |
|---|---|---|---|
| 1 | `-gdpr-compliant` | 无 | 加载 defines 后立刻退出 |
| 2 | `-gdpr-compliant -continuelastsave` | 无 | 同上 |
| 3 | `-gdpr-compliant --continuelastsave`（双横线） | 注入 `SteamAppId=281990` 等 | 存活约 120 秒后退 出 |

结论：**必须通过启动器（或 Steam）启动**。启动器还负责游戏正常运行所需的启动环境
（未捕获到具体是什么；`-pdx-launcher-session-token` 字符串虽在 exe 中，但启动器日志
显示并未传它）。

**修正 1.1 节**：`dlc_load.json` 决定「加载哪些 mod」依然正确，但
「直接跑 exe 等同于点 PLAY」**是错的**。

### 8.2 参数形态（启动器日志给出的确切值）

```
launcher-2026-09-16.log:
  stellaris.exe in D:\SteamLibrary\steamapps\common\Stellaris with the following arguments:
      --continuelastsave,-gdpr-compliant      <- 「继续」
      -gdpr-compliant                          <- 「开始游戏」
```

**是双横线 `--continuelastsave`** —— exe 字符串里搜到的是单横线片段，具有误导性。

### 8.3 「存档消失」的重大嫌疑：autosave_tocloud=yes

`settings.txt` 现状：

```
autosave=5
autosave_tocloud=yes      <- 自动存档同步到 Steam 云
```

**实机现象**（09-16 00:36 -> 00:38）：某战役目录里的 3 个年度存档在 2 分钟内被整体
清空。结合「一局跑了 38 年却一个存档都不剩」，云同步（或其冲突）是头号嫌疑。

**建议**：`autosave_tocloud` 改为 `no`，让年度存档稳定留在本地。
（涉及时户 Steam 云策略，改动前须征得同意。）

### 8.4 启动器按钮为什么点不动

- 启动器是 Electron 应用，窗口位置/大小每次启动都变；
- 系统显示缩放 125%（物理 1676x850 vs 逻辑 1341x680），坐标易错；
- 实测 `SetCursorPos + mouse_event` 与 `click-ratio`（窗口内比例）均未生效；
- PowerShell `Add-Type`（UIA 方案）被安全策略禁止；
- 可行路线：装 Python UIA 库（如 `uiautomation` + comtypes）、改用 `SendInput`
  API、或请用户点一次 PLAY。
