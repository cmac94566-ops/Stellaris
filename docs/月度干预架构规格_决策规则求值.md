# 月度干预架构规格 —— LLM 决策规则 + 运行时按月求值

> 决策来源：用户 2026-09-16。
> **第一版（逐月指令表）已被用户否决**，理由一针见血：
> 「局势变化你的决策就失效了」—— 提前排好的逐月指令表越详细越僵，局势一变就是废纸。
> **本版为修订方案（v2，含复合条件）。**
> 性质：架构级变更（Lex 从「8 槽循环 + 固定日程」→「规则集 + 实时求值」），影响 mod 数据结构与 M2 pipeline。

---

## 0. 设计公理（A1，最高优先级，一切实现不得违反）

> **A1 —— 给规则，不给计划表。**
> 用户 2026-09-16 定调：「对灵活应对，**给规则比给计划表重要**。」
>
> | | 计划表（禁止） | 规则（必须） |
> |---|---|---|
> | 形态 | "第 N 月做 X" 的**时序指令** | "什么条件做什么" 的**判断函数** |
> | 失效条件 | 局势一变即废（**必然发生**） | 无需重写，输入变则输出变 |
> | 对加速跑 | 跑越快越早过期 | **完全无关** |
> | 谁在决策 | 编译时的 LLM（一次性） | **运行时的引擎**（每月，用实时局势） |
>
> **推论（四条硬约束，写代码时逐条对照）：**
> 1. **禁止任何形态的时序排程**（不排"1 月 A、2 月 B"）。规则的**顺序**只表示**优先级**，不表示时间。
> 2. **决策的输入必须是运行时实时局势**（当月求值），不得是编译期快照。
> 3. **规则表达力优先于实现简便** —— 遇到"规则表达不了这个判断"时，
>    应当**扩展规则语义**（见 §3.2 复合条件），而不是退回计划表或把判断硬编进代码。
> 4. **一个月内可多线并行（A2，用户 2026-09-16 追加）** —— 决策不是"每月只挑一件事做"，
>    而是"每月把该做的几件事**同时**推进"。求值**不早停**：所有规则全部求值，命中的都执行
>    （受同相位互斥与并行上限约束，见 §3.3）。**这与 A1 不冲突**：并行的是"当下局势要求的多个方向"，
>    仍然是实时求值的产物，不是预排的动作清单。
>
> **A3 —— 看收益，条件成立不等于该做。** 用户原话（2026-09-16）：
> 「**每个月内有条件推进的就推进，推进反而结果不好的暂时不做，还是要看收益**。」
>
> | | 只看条件（v3 的漏洞） | **看收益（v4，本版）** |
> |---|---|---|
> | 判据 | 条件成立 ⇒ 执行 | 条件成立 **且** 近期有正收益 ⇒ 执行 |
> | "命中就做" | ✅ 一律做 | ❌ **收益不好的先不做**（熔断） |
> | 最终裁判 | 条件 | **收益**（高于条件） |
>
> **推论：**"有条件推进的就推进"是**前提**（条件成立就别犹豫，要推）；
> 但**收益是最后一道门** —— 连续 N 个月做了却没带来正收益 ⇒ **暂时不做**，等局势变了再给机会。
> **"暂时"是关键词**：熔断必须可解除，不是永久封杀（见 §3.3 熔断解除 4 条）。
> 实现基础已具备：各相位现有 `om_did_build` 旗标 + 「动作成功才写」日志（可区分空转与真落地）。
> 现实依据：月度 tick 内**早已有并行先例** —— `overmind_autonomy_situations`（S-12 赤字应对）与
> `overmind_autonomy_agenda`（S-13 内阁议程）**每月无条件执行**，与"本月轮到的相位"并行。
> 本版把这一机制**从"特例"推广为"常规"**：相位选择也变成多命中并行。

## 1. 设计转变（一句话）

| | 旧（已否决） | **新（本版）** |
|---|---|---|
| LLM 产出 | 逐月**指令**（1 月干 A、2 月干 B…） | **决策规则**（什么条件下做什么，含优先级） |
| 决策时刻 | 编译时（一次性） | **每月运行时**（用当月的真实局势求值） |
| 局势变化 | ❌ 计划失效 | ✅ **规则本来就为"局势变化"而存在**：输入变 → 输出自动变 |
| **决策粒度** | 每月 **1 个**动作 | **每月多线并行** —— 有条件的都推进（A2） |
| **收益门（A3）** | 无（命中即做） | **近期无正收益 ⇒ 暂时不做**，局势变了再给机会 |
| LLM 干预频率 | 每月都要新表 | 规则集更新即可（局势大类变化时 / 定期），不必每月重载 |

一句话：**LLM 写"决策函数"，游戏每月用最新局势调用它** —— 这样"每月都在决策"与"局势变了不失效"同时成立。

## 2. 引擎硬边界（约束依旧）

- Clausewitz **不能运行时调用外部程序**，游戏**不能暂停等 LLM 回复**。
- ⇒ 「每月实时问一次 LLM」不可行；LLM 的输入必须是**已落盘的规则**。
- ⇒ 但**求值发生在游戏内、用实时数据** —— 这正是本方案能避开"失效"的关键。

## 3. 数据结构（`common/scripted_variables/overmind_lex_vars.txt`）

### 3.1 规则编码

| 变量 | 含义 |
|---|---|
| `om_lex_rev` | 规则集版本号（严格递增，与 M2-1 现有 rev 通道对齐） |
| `om_lex_rule_count` | 规则条数（默认 12，上限 24） |
| `om_lex_parallel_max` | **本月并行上限**（A2 新增）：默认 **3**，范围 1..8。命中集超出则按优先级截断（防 effect 预算爆） |
| `om_lex_gain_p1..p8` | **各相位最近一次收益分**（A3 新增）：`+1` 有正收益 / `0` 空转未落地 / `-1` 做了反而更差。由**相位自报**（相位内部最清楚自己的成功判据），求值器只读 |
| `om_lex_gain_neg_max` | **熔断阈值**（A3 新增）：默认 **3** —— 连续 N 个月收益 `≤ 0` 即熔断该相位 |
| `om_lex_gain_pN_streak` | 连续无正收益月数（A3 新增，8 个）。熔断判定与解除均读它 |
| `om_lex_rule_N_cond` | 第 N 条规则的**主条件码**（见 3.2；`0` = 无主条件） |
| `om_lex_rule_N_cond2` | 第 N 条规则的**副条件码**（`0` = 无副条件，即单条件规则） |
| `om_lex_rule_N_op` | 组合算子：`1`=AND，`2`=OR，`3`=NOT（仅作用于 `cond2`） |
| `om_lex_rule_N_act` | 第 N 条规则的**动作**（相位 1-8） |
| `om_lex_rule_N_prio` | （可选）显式优先级，缺省即"行号"；用于 LLM 微调顺序而不改行序 |

> **复合条件（v2 新增，用户原则直接推论）**：规则形如 `(cond) [op] (cond2) → act`。
> 例：`能源赤字 AND era>=era3 → RELIEF`、`威胁高 OR 正在战争 → MILITARY`、`NOT 住房不足 AND 有可拓土 → 扩张`。
> **单条件是复合条件的退化情形**（`cond2 = 0`），因此只需一套求值器，无额外分支。
> **上限一条**（`cond + cond2`）：足以表达绝大多数判断，且把变量数压在 4 字段/条以内，避免触脚本变量上限。
> 若将来确需三层嵌套，再评估"显式布尔表达式编码"（优先级低，不本版做）。

> ⚠️ **变量必须显式初始化（zcode 2026-09-16 答复，D-6 家族教训）**：
> **未设置的脚本变量读数即假**，求值器不得依赖未初始化读数。
> ⇒ 全部新增变量（`om_lex_rule_*` / `om_lex_gain_*` / `om_lex_parallel_max`）**必须在 `lex_apply` 内显式赋初值**。
> 变量**总量不触限**（Clausewitz 国家变量无硬上限；v4 全量后约 90+，内存与解析成本可忽略，zcode 已核）。
> 缺省约定：`cond2 = 0` = 单条件（条件码从 1 起，**0 永远非法**）；`op` 缺省 `1`（AND）。

### 3.3 求值规则（每月 tick）

> **v3 核心（A2）：求值不早停，命中的都执行 —— 这就是"并发"。**

1. **按 `N = 1..rule_count` 顺序全量求值**（不早停，不"命中第一条就收工"）
2. 每条规则先算**条件真值**（复合条件按 `op` 组合）：
   - `cond2 = 0` → 真值 = `cond` 是否成立（单条件）
   - `op = 1 (AND)` → 真值 = `cond` **且** `cond2`
   - `op = 2 (OR)` → 真值 = `cond` **或** `cond2`
   - `op = 3 (NOT)` → 真值 = `cond` **且非** `cond2`
   - 任何**条件码非法/未知** → 视为**假**（不得因脏数据中断月度 tick），并打一条 `【求值】忽略非法条件码`
3. **【A3 收益门】真值成立 ≠ 该做** —— 入执行集前先过收益检查：
   - 若 `om_lex_gain_p{act}_streak >= om_lex_gain_neg_max` ⇒ 该相位**已熔断**，本月**跳过**
     （跳过**不占** `om_lex_parallel_max` 配额），并打一条 `【熔断】` 日志
   - 未熔断 ⇒ 正常入执行集
   - **收益记账（执行后）**：相位跑完自报 `om_lex_gain_p{act}`（`+1`/`0`/`-1`），
     求值器更新 `streak`：本月收益 `≥ +1` → `streak = 0`；否则 `streak += 1`
     - 实现基础已具备：各相位现有 `om_did_build` 旗标 + 「动作成功才写」日志 ⇒ **空转（0）已可判定**；
       `-1`（做了反而更差）由能做量化判据的相位自报，做不了的**默认记 0**（不冤枉，也不纵容）
   - **熔断解除（4 条，"暂时"不是"永久"）**：
     ① 该相位的命中条件组合变了（局势变了 ⇒ 值得再试一次）；
     ② `om_era` 切换（年代变了 ⇒ 阈值环境变了）；
     ③ 规则集换版（`rev` 递增 ⇒ 新策略，清零重来）；
     ④ 兜底**永不熔断**（保证零命中时有事可做）
4. **所有通过收益门的规则都计入「本月执行集」⇒ 多线并行**。三条落地细节：
   - **同相位去重**：多条规则指向同一 `act` 时只执行**优先级最高（行号最小）**那条（同月同相位跑两遍无意义）
   - **执行顺序**：按行号**依次**落地（引擎 tick 本就顺序执行）⇒ 资源**累计消耗**，靠前的先吃饱；
     LLM 用**规则顺序**表达"先保谁"—— 这是唯一的资源仲裁手段，够用
   - **并行上限**：执行集 > `om_lex_parallel_max` 时按行号截断（默认 3；防嵌套加深撞 effect 预算）
5. **兜底规则（`cond = 99`）只在「执行集为空」时执行** —— ⚠️ **语义修正（v3 必改）**：
   多命中模式下"永远成立"会让兜底每月白做一次，故求值器**特判** `cond = 99`，不计入普通命中集。
   **兜底永不熔断**（A3 例外）—— 否则零命中时会彻底无事可做。
6. 若规则集缺失 / 非法 → **回退现有 8 槽轮转**（绝不空转）
7. **与既有"每月必做"并存**：`overmind_autonomy_situations`（S-12 赤字应对）与 `overmind_autonomy_agenda`（S-13 内阁议程）
   **维持每月无条件执行，不占 `om_lex_parallel_max` 配额**（独立通道，已有实现）。
   ⇒ 每月实际动作数 = **必做 2 条 + 执行集（≤ parallel_max）**

### 3.4 可观测性（必须能看出"为什么这么决策"）

每月打一条汇总 + 必要时的冲突/截断说明：
```
OVERMIND: 【求值】命中 3/12 条 → 执行集 [相位 1/8 RELIEF, 相位 3/8 JOBS, 相位 5/8 SCIENCE]（rev=7）
OVERMIND: 【求值】同相位冲突：规则 #2 与 #5 均指向相位 1，取 #2
OVERMIND: 【求值】执行集超上限 3 → 截断至 [相位 1, 相位 3]（丢弃规则 #7）
OVERMIND: 【求值】本月零命中 → 执行兜底相位 4/8 AMENITIES（rev=7）
OVERMIND: 【收益】相位 1/8 RELIEF 本月 +1（赤字消除）→ streak 归零
OVERMIND: 【熔断】相位 6/8 MILITARY 连续 3 月无正收益 → 本月跳过（streak=3，未占配额）
OVERMIND: 【熔断解除】era 切换 → 相位 6/8 MILITARY streak 清零，重新给机会
```

## 4. 游戏内时间轴（用户追加要求的落实）

- **求值单位 = 游戏内月份**（`om_month`），与本方案天然一致（求值发生在 tick 内）✅
- **规则集更新（换版）**：由 LLM 侧生成新 `om_lex_rule_*` + `rev+1` → **须重载生效**（同一硬边界）
  - ⚠️ 两条时间轴解耦：**"何时该更新"由游戏内局势判定**（如连续 N 年只命中兜底 → 说明规则不适配），
    **"何时能更新"由现实操作决定**（用户在重启/载入存档时机执行）
  - 加速跑不会造成换版压力（规则与时间无关，只与条件有关）——**这正是本方案优于上一版的第二点**

## 5. 验收标准（交 zcode 实现时按此写守卫）

1. **顺序即优先级**：注入「调换规则 1/2 的顺序」→ 求值结果必须变化（守卫断言顺序敏感）。
2. **兜底必须存在**：规则集不含 `cond = 99` → 守卫失败。
3. **降级可用**：规则集缺失/非法 → 回退 8 槽轮转（注入「删掉回退」→ 守卫失败）。
4. **日志可解释**：必须同时输出「命中规则编号/条件」与「实际相位」，无命中时输出「兜底」。
5. **实机**：制造一次能源赤字 → 次月日志显示命中赤字规则；赤字消失后 → 回到兜底/其它规则。
   （**这条直接验证"局势变化决策不失效"**）
6. **复合条件求值正确**（v2 新增）：注入 `能源赤字 AND era>=era3 → RELIEF`，
   - 在 era1 + 能源赤字下**不得**命中该规则（应落到后序规则）；
   - 在 era3 + 能源赤字下**必须**命中。
   三种 `op`（AND/OR/NOT）各覆盖一路。
7. **脏数据不中断**：注入未知条件码 → tick 正常跑完 + 打忽略日志（注入「删掉容错」→ 守卫失败）。
8. **多线并行（A2 核心）**：制造两条不同相位同时成立 → 日志执行集含**两项**，且两相位效果**都实际落地**
   （注入「求值早停」→ 只执行一条 → 守卫失败）。
9. **同相位去重**：注入两条指向同一相位的规则 → 执行集只含一项，且取行号小者。
10. **兜底特判（v3 语义修正）**：有命中时**兜底不得执行**（注入「兜底无条件执行」→ 守卫失败）。
11. **收益熔断（A3 核心）**：注入某相位连续 `neg_max` 月收益 `≤ 0` → 该相位**不得**出现在执行集，
    且**不占**并行配额（注入「删掉收益门」→ 命中即做 → 守卫失败）。
12. **熔断可解除（"暂时"不是"永久"）**：触发任一解除条件（条件组合变 / era 切换 / rev 递增）→
    `streak` 清零，该相位**必须能重新执行**（注入「熔断后永不再试」→ 守卫失败）。
13. **兜底不熔断**：兜底相位即使长期无正收益，仍须在零命中时执行。
