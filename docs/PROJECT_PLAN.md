# Stellaris Overmind — 项目计划书

| 项 | 内容 |
|---|---|
| 项目代号 | Overmind（大模型接管玩家帝国） |
| 版本 | plan v1（2026-09-14） |
| 形态 | 单机 mod + 本地大模型引擎 + 编译式注入 |
| 目标平台 | Stellaris 4.4.6（Steam，`D:/SteamLibrary/steamapps/common/Stellaris`） |
| 决策者 | 用户（需求与阶段验收的最终裁定方） |
| 执行者 | 本 agent |

---

## 1. 项目目标

让**本地大模型**成为玩家自己帝国的**执政者**：制定长期方针、逐月决策、自主建设与作战，
全程**不使用控制台、不需要玩家手动操作**，并可持续迭代（每次载入游戏自动换上新一版方针）。

**一句话**：大模型写"帝国法案"，游戏在内部逐月执法。

### 1.1 已确认的显式诉求（来自对话，非推断）

| 编号 | 诉求 | 来源 |
|---|---|---|
| G-1 | 控制对象是**玩家自己的国家**，不是 AI 帝国 | 用户原话"我的诉求一直是 ai 控制我的国家" |
| G-2 | **脱离控制台**，不要靠键盘注入敲命令 | 用户原话"我希望脱离控制台 ai 自主游玩" |
| G-3 | 由**大模型**掌舵，不是游戏自带 AI | 用户原话"游戏自带的 ai 太蠢了，所以我才考虑大模型" |
| G-4 | 实现要**聪明**，路线繁琐就换路线 | 用户原话"务必用聪明的方法实现" |
| G-5 | 覆盖群星**完整玩法面**，不只是局部 | 用户原话"我还只是说了游戏内容的一部分" |
| G-6 | 按**标准项目流程**推进，先不动手 | 用户原话"按标准项目流程来做，不要急着动手" |

### 1.2 已裁定的取舍

| 议题 | 决策 | 依据 |
|---|---|---|
| 成就 vs 接管 | **接管优先**，本局放弃成就 | 用户在本轮选择"接管优先（推荐）" |
| 决策节奏 | **每次重载游戏换一版法案** | 用户选择"每次重启换一版法案" |
| 游戏原生 AI 接管（`-human_ai`） | **否决** | 原生 AI 太蠢；且属开发开关，杀成就 |

## 2. 硬约束（全部为实测确证，非推断）

这一节是全项目的地基。任何设计如果违反其中一条，方案即无效。

| 编号 | 约束 | 确证方式 |
|---|---|---|
| **C1** | Clausewitz 引擎**读不了运行时外部文件**，也**没有远程控制台**。游戏唯一愿意读外部世界的时刻是**脚本加载时** | 早前对 `stellaris.exe` 的全量字符串搜索（`remote console` / `-console` 端口均为 NOT FOUND）；本引擎无文件读取入口 |
| **C2** | **成就与接管不可兼得**：① 使用控制台命令一次即永久失效；② mod 修改 `common/`、`events/` 会改校验码，成就失效（4.x 已取消铁人要求，但校验码要求保留） | 官方/中文维基 + 2025 社区确认，两份来源一致 |
| **C3** | 脚本层**无法把建造物塞进玩家的建造队列**（不存在"入队"effect）。`add_district` / `add_building` / `add_zone` / `create_ship` / `create_colony` 都是**即时生效** | exe 命令表里 `add_*_to_build_queue` 全部带 `_command` 后缀 = 仅控制台；vanilla 脚本零调用 |
| **C4** | 4.4.6 **没有通用工业区划**，被 `zone` 体系取代；`add_zone` 需指定宿主区划 | 游戏数据实测；旧别名 `industrial` 会被模糊匹配到游牧方舟专用区划（曾造成静默失效） |
| **C5** | mod 重定义 `on_action` 是**合并语义**，可以只列自家事件 | 以已装且正常的 NSC、Real Space 为旁证（二者都只列自家事件） |
| **C6** | 引擎存在启动开关：`-continuelastsave`、`-human_ai`、`-berserk_ai`、`-overnight`、`-game_paused false` 等 | `stellaris.exe` 命令行参数表实测提取 |
| **C7** | 脚本层**可用的动作名共 4,326 个**（15,074 个 exe 候选经官方脚本调用确认） | `scripts/mine_action_vocabulary.py` 产出 `docs/ACTION_VOCABULARY.md` |
| **C8** | 大模型**不能直接产生脚本**——必须经编译器映射到封闭取值域，否则会写出语法非法的脚本 | 设计约束；已用生成器保证（`engine/strategy_lex.py`） |

## 3. 范围

### 3.1 范围内（In Scope）

| 编号 | 内容 |
|---|---|
| S-1 | 大模型战略输出 → 校验 → 编译为 mod 脚本（"法案"） |
| S-2 | 游戏内自治执行层：逐月自检帝国状态并行动 |
| S-3 | 零控制台启动链路（读档 → 编译 → 启动） |
| S-4 | 存档回流：把执行结果读回来，供大模型修订下一版法案 |
| S-5 | 动作覆盖：经济/建造/科研/传统/飞升/舰队/战争/外交/内政 |
| S-6 | 质量门禁：脚本 ID 审计器、error.log 门禁、回归测试 |
| S-7 | 完整文档：计划、需求、架构、缺陷、动作清单 |

### 3.2 范围外（Out of Scope，已评估并排除）

| 方案 | 排除理由 |
|---|---|
| 内存读写 / DLL 注入 | 高危，随版本失效，触碰反作弊边界 |
| 多人 UDP 协议注入（参考 imperial-auto-governor） | 需联机 + 管理员抓包 + 协议逆向，单机不可用 |
| 替换 C++ 决策层（AI minister modules） | 决策层在 C++，脚本层无 hook |
| 键盘注入控制台（`inject_console.py`） | 用户明确否决；且杀成就 |
| 游戏原生 AI 接管（`-human_ai`） | 用户否决（太蠢 + 杀成就） |
| 保成就 | 已裁定让位于接管（见 1.2） |

## 5. 阶段与里程碑

每个里程碑结束时做一次**验收评审**（用户裁定），通过才进入下一阶段。

| 里程碑 | 内容 | 出口条件（可测） |
|---|---|---|
| **M0 立项与基线** ← 当前 | 计划书、需求规格、架构、缺陷清单、动作清单 | 三份文档产出 + 用户签字 |
| **M1 执行层 v1** | 8 相位自治（经济/住房/就业/民生/科研/军备/传统飞升/战争防御）；审计器修好并成为门禁 | 审计 0 违规；error.log 无 mod 报错；10 年长跑指标单调增长 |
| **M2 法案闭环** | 编译器 + 启动器 + 存档回流；每次重载换版 | 法案版本号在存档变量中随重载切换可见 |
| **M3 战斗深化** | 舰船设计（自有设计或按兵种选 vanilla 设计）/ 编成 / 战争目标 / 陆军 / 轰炸姿态 / 星港 | 一场战争中能自主宣战、达成战争目标、占领星球 |
| **M4 内政外交深化** | 传统树全序 / 内阁议程 / 政策 / 联邦与附庸 / 星海共同体决议 / 情报 | 覆盖 `ACTION_VOCABULARY` 七大领域中 ≥ 60% 的高频动作 |
| **M5 长跑验收** | 无人干预长跑 N 年 | 存档不损坏、无 error.log 新增错误、指标曲线合理 |

### 5.1 关键路径

```
M0（现在）→ M1 执行层 → M2 闭环 → M3 战斗 → M4 内政外交 → M5 长跑
                 ↑                              ↑
            审计器门禁 ─────────────────────────┘
```

M1 与 M2 之间可并行做 M3 的动作调研（只读游戏数据，不写脚本）。

## 6. 缺陷与风险登记册

### 6.1 已发现缺陷（待修，M1 前置）

| 编号 | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| D-1 | 审计器把**键名**当 ID：`district_type = $TYPE$` 被报成未知区划 | `overmind_autonomy.txt:37` 误报 | 误报会掩盖真缺陷，审计器不能当门禁 |
| D-2 | 审计器只扫游戏定义，**不认 mod 自己定义的 ID** | `opinion_overmind_goodwill`（mod 内定义）被报未知 ×3 | 同上 |
| D-3 | `scripts/overmind_takeover.py` 默认仍带 `-human_ai` | 代码默认值 | 与已裁定决策（否决原生 AI 接管）冲突 |
| D-4 | 自治层未覆盖战斗与飞升传统 | 相位仅 6 个 | 不满足 G-5 |

### 6.2 风险

| 编号 | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R-1 | **静默失效**：ID 或 trigger 写错，游戏不报错但什么也不发生 | 高 | 高 | 审计器（修好后）+ 强制读 error.log |
| R-2 | 费用模型与真实成本偏离，帝国凭空暴富/破产 | 中 | 中 | 从 `common/districts`、`common/buildings` 的 `resources` 块读取真实造价生成费用表，而非手填 |
| R-3 | 每月遍历全国星球造成脚本卡顿 | 中 | 中 | 限额标记（每月每类最多一次）+ 随机取样 |
| R-4 | 与其他 mod 冲突（on_action 合并、同名 key） | 中 | 中 | 全部命名空间化（`overmind_` / `om_`），on_action 合并语义已确证 |
| R-5 | 大模型输出越界 | 中 | 高 | 封闭取值域 + 编译器校验 + 审计器；大模型**永不直接产出脚本** |
| R-6 | 存档变量污染不可逆 | 低 | 中 | 只写 `om_*` 命名空间；提供"清除主脑痕迹"脚本 |
| R-7 | 玩家预期管理：成就已失 | 高 | 低 | 已在 edict 描述与本文档明示 |
| R-8 | Clausewitz 不热重载，每次改动都要重开游戏，迭代慢 | 高 | 中 | 尽量把可变部分集中到法案文件；批量验证 |

## 7. 变更控制

1. **需求变更**：改动 SRS 对应条目 + 标注影响范围 + 用户确认，才动手。
2. **设计变更**：写入 ADR（架构决策记录）一节的"决策/理由/被否方案"。
3. **缺陷处理**：先落 `docs/BACKLOG.md`，标严重度，再修；修完补回归测试。
4. **每次交付必须附带**：实测数据（测试数、审计结果、日志证据）+ 未验证项清单。
