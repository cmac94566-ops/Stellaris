## 0. 一句话结论

D-25 列的三条里，**②「双重扣减」经取证不成立、①「按距离排序」在现行结构下收益为零**，
**只有 ③「殖民优先于拓土」是真问题**。因此本规格的落地范围收窄为
**一个顺序调整 + 一道预留门**（两个 else/AND 分支），
并按「原诉求不成立」给出可验证的推翻证据，避免后续再按旧描述返工。

| 原条目 | 取证结论 | 处置 |
|---|---|---|
| ① 按距离排序取最近无主星系 | **不成立（推断级，证据见 §2.1）**：现行选择器保证目标恒为「与我有星港系统相邻的无主星系」⇒ 恒 1 跳 ⇒ 代价恒定，排序换不来任何东西 | **不做**。改为登记「未来跨跳拓土条款」（§5） |

## 1. 现状（只读实测，非估计）

### 1.1 拓土分支 —— `mod/stellaris_overmind/common/scripted_effects/overmind_autonomy.txt:2904-2937`

```text
overmind_expand_try_outpost = {
	if = {                                        # ← 单分支，无 else
		limit = {
			check_variable = { which = om_out_built value < 2 }
			overmind_can_afford = { RESOURCE = alloys PAD = 100 }
			resource_stockpile_compare = { resource = influence value >= 75 }   # ← (a) 静态 75
			any_system_within_border = { exists = starbase
				any_neighbor_system = { NOT = { has_owner = yes } } }
		}
		random_system_within_border = {                       # ← (b) 随机起点
			limit = { exists = starbase
				any_neighbor_system = { NOT = { has_owner = yes } } }
			random_neighbor_system = {                        # ← (c) 随机目标
				limit = { NOT = { has_owner = yes } }
				create_starbase = { size = starbase_outpost owner = root } } }
		change_variable = { which = om_out_built value = 1 }
		add_resource = { influence = -75 }                    # ← (d) 静态扣费
		add_resource = { alloys = -100 }
		log = "OVERMIND: 前哨拓土 —— 新星系并入疆域（影响力 -75，合金 -100）"
	}
}
```

### 1.2 殖民分支 —— 同文件 `:2940-2962`

门控：`om_col_built < 1` + `overmind_can_afford { minerals PAD = 300 }` +
`influence >= 100` + `any_planet_within_border = { is_colonizable = yes }`。
扣费：`minerals -200`、`influence -100`。

### 1.3 调用序（关键）—— 同文件 `:3497-3509`

```text
overmind_autonomy_expand = {
	overmind_expand_try_mining   = yes
	overmind_expand_try_mining   = yes
	overmind_expand_try_research = yes
	overmind_expand_try_research = yes
	overmind_expand_try_outpost  = yes        # ← 先
	overmind_expand_try_outpost  = yes        # ← 先
	overmind_expand_try_colony   = yes        # ← 后（影响力在同一池里被拓土先取）
}
```

**影响力池是同一个**：单月最多被取走 `2×75（拓土）+ 1×100（殖民）= 250`，
而本局实测影响力收入仅 **2~4/月**（`docs/胜利路线图.md` §5、D-25 原始证据「拓土间隔 11/19/20 月」）。
⇒ 顺序即优先级：**拓土可能把殖民的钱吃光，而殖民的分值（50 分 + 研究岗位）远高于拓土（10 分）**。

## 2. 取证（本机语料 + 社区，分级标注）

### 2.1 ① 为什么「按距离排序」不成立 —— 证据链（推断级，但证据闭合）

| # | 证据 | 出处 |
|---|---|---|
| E1 | 前哨站影响力成本 = **75 × 跳跃数**，从「**帝国最近的已拥有星系**」起算；相邻（1 跳）= 75，2 跳 = 150 | 社区（**Wiki verified 4.3**，低于本机 4.4.6，标注为口径参考）+ 论坛共识（RPGnet 2022 帖：「influence cost scales directly with how many jumps it is away from the closest system you own」） |
| E2 | defines 三常量：`EXPANSION_COST_MAX = 1000.0` / `EXPANSION_COST_BASE = 75.0`（outpost 基础影响力成本）/ `EXPANSION_COST_DISTANCE = 75.0`（每跳递增） | `common/defines/00_defines.txt:2028-2030`（**本机确证**） |
| E3 | 现行选择器**结构上保证**目标是我方「带星港系统」的**直接邻居** | 代码 `:2910-2915` + `:2917-2930`（`any_neighbor_system` / `random_neighbor_system`，**本机确证**） |

**推论**：E3 ⇒ 目标与最近已拥有星系相距 **恰好 1 跳** ⇒ 按 E1/E2 成本**恒为 75（无修正基准）**
⇒ 无论选哪个候选，代价相同，**「按距离排序」不改变任何决策结果**。

> 社区同时给出「不要跳星系（snaking）」的结论（同上帖：跳过中间系统不省事、反而更贵），
> 与我们的现行结构**同向**——现行结构天然就是 snaking。

**残余风险（不掩盖）**：若将来引入「跨跳抢咽喉/关门」策略，成本即随跳数上升，
届时必须按 §5 的分级成本条款计价，不能沿用固定 75。

### 2.2 ② 为什么「双重扣减」不成立 —— 证据链（推断级，含实机判据）

| # | 证据 | 出处 |
|---|---|---|
| E4 | 星堡等级**数据文件里没有任何成本字段**：`common/starbase_levels/00_documentation.txt` 列出的全部合法键为 `ship_size / next_level / level_tooltip / show_in_outliner / display_empire_shield / display_map_icon / level_weight / ai_weight / picture / potential_home_base / can_always_dismantle / display_shipyard_button / module_slots / building_slots / downgrade_potential`（`starbase_capacity_used` 见实文件）——**无 cost / influence_cost / build_cost** | `common/starbase_levels/00_documentation.txt`；`00_starbase_levels.txt:3-15`（outpost 定义仅 `ship_size / next_level / level_weight / ai_weight / picture`）（**本机确证**） |
| E5 | 原版 **120 处** `create_starbase` 全部是**授予**语义（危机 / 堕落帝国 / 游牧 / 前 FTL / 初始星系），**零处伴随 `add_resource` 扣减**——危机与堕落帝国显然不该付玩家影响力 | 全库 `create_starbase` 命中 120 处（`common/`+`events/`），例：`fallen_empire_scripted_effects.txt:231-248`、`marauder_scripted_effects.txt:202`、`02_machine_age_effects.txt:1083`（**本机确证**） |
| E6 | 原版凡「玩家应付费」的场合**一律手写扣费**（全库 `influence = -` 共 **150 处**）；其中 `events/aquatics_events.txt:700` 恰为 `add_resource = { influence = -75 }`，与选项 `allow` 里的 `influence >= 75` 配对——**这正是「脚本不自动扣费所以要自己扣」的写法** | `grep -rn "influence = -" common/ events/` = 150 处；`events/aquatics_events.txt:676-702`（**本机确证**） |
| E7 | 前哨站的建造成本在官方口径里是**建造行为**（UI/建造命令）的成本：「Constructing a starbase requires first fully surveying the desired system. The build cost is 100 alloys if Mechanical shipset or 50 alloys and 175 food if using Biological shipset, and an additional influence cost on top of that.」 | Wiki **verified 4.3**（低于本机 4.4.6 ⇒ 标为口径参考） |

**结论**：`create_starbase` 是**纯授予型 effect**，引擎不为它扣任何资源；
我方 `add_resource { influence = -75 }` / `{ alloys = -100 }` 是**唯一**扣费。
⇒ D-25 原描述的「避免双重扣减」**不存在**，无需修改。

**实机判据（留给下局核销，写入对账清单）**：
拓土成功月，`game.log` 的 `OVERMIND: 前哨拓土` 行**前后两个月**影响力库存净变化应为 **−75**（含当月收入）。
若观测到 **−150 量级**（≈ 手工 75 + 引擎 75），则本推断被推翻 ⇒ **必须移除手工扣费、门控改由引擎承担**。

### 2.3 ③ 殖民优先 —— 为什么是真问题

- 同一影响力池 + 调用序（§1.3）⇒ 拓土先取 2×75，殖民后取 100。
- 实机证据：本局影响力长期是扩张瓶颈（D-25 原始证据「拓土间隔 11/19/20 月」），
  且 D-28 已确证「有动作但建设指标不动」的产能结构错配。
- 收益不对称：**殖民 50 分 + 研究岗位**（且 V-1 结论是「赢 = 科技力最大化」）vs **拓土 10 分**。
- ⇒ 按照 A3（推进结果不好的暂时不做）：当「殖民与拓土争同一笔钱」时，**拓土应让位**。

## 3. 裁定与落地范围

### 3.1 M1 —— 调用序（顺序即优先级）

在 `overmind_autonomy_expand` 内，把 `overmind_expand_try_colony = yes` **移到两处
`overmind_expand_try_outpost` 之前**（采矿/研究槽不受影响，二者不吃影响力）。

理由：单月影响力分配 = 按调用序先到先得；殖民提前即「殖民优先」的最小实现，
且不新增任何脚本效果层数（**5 层预算不变**）。

### 3.2 M2 —— 拓土预留门（防止「殖民钱被吃光」）

给 `overmind_expand_try_outpost` 的影响力门加**预留分支**：当存在可殖民星球时，
要求影响力 **≥ 75 + 100 = 175**；无可殖民星球时维持 75。

参考片段（**触发条件内实现，不增层**）：

```text
resource_stockpile_compare = { resource = influence value >= 75 }   # 原句删除，换为：
OR = {
	AND = {
		NOT = { any_planet_within_border = { is_colonizable = yes } }
		resource_stockpile_compare = { resource = influence value >= 75 }
	}
	AND = {
		any_planet_within_border = { is_colonizable = yes }
		resource_stockpile_compare = { resource = influence value >= 175 }
	}
}
```

要点：
- 复用殖民分支**同一个**可殖民判据（`any_planet_within_border = { is_colonizable = yes }`，
  见 S-7 已落地实现），避免两处判据漂移；
- 175 = 拓土自身成本 75 + 殖民成本 100，**注释必须写出这个加法来源**；
- 不改动 `om_out_built < 2` 配额与 `overmind_can_afford { alloys PAD = 100 }`（P6 能源门不动）。

### 3.3 M3 —— 记档口径声明（不改代码，只写注释/规格）

在拓土与殖民两处扣费语句的注释里写明**记账口径**，便于日后审计：

- 影响力：**原版基准 × 跳跃数**，当前恒为 1 跳 ⇒ 75（无修正基准，
  **未计入**原版的减费修正：Devouring Swarm −50% / Fanatic Xenophobe −40% /
  Determined Exterminator −30% / Xenophobe −20% / Interstellar Dominion −20% /
  Reach for the Stars −10% —— 见 §2.1 E1 社区表，**故我方扣费是保守上界**）；
- 合金：**机械舰装口径 100 合金**（§2.2 E7）；本帝国为哺乳类舰装，适用该口径。

### 3.4 明确不做（含理由）

| 项 | 决定 | 理由（A3 口径） |
|---|---|---|
| 距离排序选点器改造 | **不做** | §2.1：现行结构恒 1 跳，改造收益为零，却要动一条跑通多轮实机的路径 |
| 移除手工扣费 | **不做** | §2.2：反向改动（若不扣就变成白送领土），且推断尚待实机核销 |
| 生物舰装扣费分支（50 合金 + 175 食物） | **登记不实现** | 本帝国非生物舰装（`uses_ship_category = bio_ship` 全库仅 13 处引用、`common/ship_sizes/00_biogenesis.txt:4` 的 `ship_category = bio_ship` 是 BioGenesis 舰装族）⇒ 当前收益为零；若将来换舰装再开 |

## 5. 未来条款 —— 跨跳拓土的分级成本（**现在不实现**，只留设计）

一旦引入「跳 1~2 个空星系去抢咽喉/关门」，成本不再是 75，必须按跳数计价：

- **原语**：`closest_system`（全库 **218 处**先例），参数 `limit` / `min_steps` / `max_steps` / `use_bypasses`；
  - 效果形态：`01_start_of_game_effects.txt:2639-2648`（`closest_system = { limit = {...} set_star_flag = ... max_steps = 3 }`）
  - 触发形态：`common/anomalies/00_anomaly_categories.txt:842-851`（`min_steps = 1 max_steps = 12 limit = {...}`）、`01_start_of_game_effects.txt:3671-3680`
  - 作用域注释：`cosmic_storms_scripted_effects.txt:1247`「**This: capital_scope (planet)**」⇒ 从「带位置的 scope」解析；**建议在 `random_system_within_border`（星系作用域）内使用**，语义无歧义。
- **计价阶梯（参考）**：`if/else_if` 逐档探测 `closest_system = { min_steps = 1 max_steps = K limit = { NOT = { has_owner = yes } } }`，
  取第一个成立的 K 作为跳跃数上界，成本 = `75 × K`（**用上界 = 保守**，宁可少拓不可超支），并按 `om_era` 分档限制 K（era1 ≤2 跳 / era3 ≤3 / era4+ ≤4）。
- **注意**：`closest_system` 只回答「[min,max] 步内**是否存在**符合条件的系统」，
  **不返回具体跳数** ⇒ 只能用「阶梯探测取上界」这一种写法，不能直接读距离。
