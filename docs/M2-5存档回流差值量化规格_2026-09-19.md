# M2-5 存档回流差值量化规格

> 版本：v1.0（2026-09-19 起草，zcode）
> 状态：**待 WorkBuddy 审**（审后动手；实现落点 scripts/overmind_metrics.py，zcode 属地）
> 数据源实证基于本局桶 `5_921109915`（2200→2350+）

---

## 1. 目的

把「两次年度档之间，自治层做了什么、效果如何」从肉眼对比变成**机械可复算的差值表**：

1. 产出量化：两次快照间，区划/建筑/区/殖民地/传统/舰队等结构增量；
2. 经济量化：八大资源 + 稀有三资源的存量差与月度收支差；
3. 动作归因：增量对应到自治层动作（om_did_* / 计数器），无法归因的标「未归因」。

## 2. 数据源（全部已在册实证）

| 源 | 内容 | 可用性 |
|---|---|---|
| gamestate（zip 解包） | om_* 计数器（om_wl_built/om_ships_built/om_out_built/om_col_built 等） | ✅ 实测在档 |
| gamestate budget 段 | 分项收支：planet_artisans/planet_miners/pop_category_* 等（锚 `budget`） | ✅ 实测（消费品核算已用） |
| metrics probe 既有解析 | 结构计数（districts/buildings/zones/colonies/pops）+ om_lex_* | ✅ 复用 |
| game.log | `om_did_*` 动作行 / `【锚地】`/`【消费品】`/`【回填】`/`【传统】判定` 等日志锚点 | ✅ 复用 |

**不做**：解析存档二进制段、反序列化完整 gamestate 对象树（成本高、收益低）。

## 3. 变量清单（三级）

### 一级 · 结构增量（Δ = 新档 − 旧档）
districts / buildings / zones / colonies / traditions / tradition_categories /
pops / empire_size / fleet_size（metrics 既有字段全部纳入）。

### 二级 · 经济差值
八大资源（energy/minerals/food/consumer_goods/alloys/volatile_motes/exotic_gases/rare_crystals）：
存量差（如可得）+ 月收入差（budget 段分项：country_base / planet_* / pop_category_*）。

### 三级 · 动作归因
- **计数器差**：om_ships_built / om_out_built / om_col_built / om_wl_built 的 Δ
  （om_ships_built 已旗标守护跨会话累计——D-34 修法后语义为「一局累计」）；
- **日志动作行计数**（窗内）：【锚地】【贸易枢纽】【消费品】【回填】【传统】判定=可采纳/
  采纳传统树/授予飞升天赋/新建了一支军用舰队/建了采矿区划 等；
- **归因规则**：某结构增量若与某动作行/计数器差同窗出现 ⇒ 归因该动作；否则标 `未归因`
  （玩家手动/AI/他 mod）。**归因只标注，不推断因果强度**。

## 4. 输出格式

```
py scripts/overmind_metrics.py --diff <旧档> <新档> [--json]
```
- 人类可读：分三段表（结构 Δ / 经济 Δ / 动作归因）；
- `--json`：机器可读（供 cron 与台账引用）；
- 每项附 `(旧值 → 新值)` 原值，避免只看差值丢上下文。

## 5. 验收标准

1. 对 `5_921109915` 任取相隔 ≥10 档的两个年度档，输出完整三段表；
2. 结构 Δ 与 game.log 窗内动作行计数**交叉一致**（如 districts Δ=+2 且窗内
   「建了 … 区划」行 ≥2，或差值可由日志解释）；
3. 未归因项**显式列出**（不藏）；
4. `--json` 可被 verify_session/台账脚本直接消费。

## 6. 边界

1. **不改任何判据/阈值/策略**（纯观测工具）；
2. 归因是**标注不是证明**（相关窗口重合 ≠ 必然因果，报告中如实措辞）；
3. 跨局样本不得混用（铁律 18）；异局桶直接拒绝并报错；
4. 大档解析只取所需段（budget/planets/country），不做全量正则回溯（灾难性回溯教训）。

## 7. 参考实现（2026-09-19 21:5x 用户签字批准采纳）

- **参考项目**：gitmaan/stellaris-companion（MIT，2026-08 活跃）——其核心机制即本规格的同构实现：
  每个存档解析后入库 **SQLite 快照**，跨档**按域 diff**；
  域划分 = military / economy / diplomacy / leaders / planets / **starbases** / technology。
- 与本规格三段表对照**取舍**：域划分是参考不是约束，验收仍以本规格 AC-1..AC-4 为准；
  「starbases 单列一域」值得吸收（我们 V-6 模块审计正需要）。
- **Rust jomini 流式解析**（iter-save --format jsonl）为**可选评估项**：是否引入新依赖由实现方评估，
  并在交付说明写明理由；默认沿用 zipfile + 按段截取（灾难性回溯教训仍在）。
