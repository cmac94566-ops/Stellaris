## §0 摘要（结论先行）

1. **V-9 不是"未来的风险"，是当下正在发生的损失。** 本局我方三类领袖**全部超容**：
   commander **5** / scientist **5** / official **4**，而每职业 cap 基线 **3** ⇒ 该职业**全部**领袖
   承受 维护 **+66.7% / +66.7% / +33.3%**、经验 **×0.7225 / ×0.7225 / ×0.85**（envoy 不计容量）。
2. **在途实现 `overmind_autonomy_prune_leaders`（S-15d）本会话零触发**，且其判据与 cap 口径
   **不是同一个量**：判据是"**空闲**指挥官 > 2"，要解决的问题是"**总数** > cap"。
   ⇒ **门与问题脱钩**（D-39「门在却不生效」/ D-49「非法比较式」**同族**失效模式）。
   且**只覆盖 commander**，scientist / official 的超容无任何处置。
3. **cap 不可读**（本机三方语料一致，检索范围见 §7）⇒ 规格**禁止**写 `count < leader_capacity`
   这类比较式（右值不可读 ⇒ 恒假/恒真陷阱，D-49 教训）；改用**每职业常数**——
   与原版先例同法（`num_owned_leaders < 8`，`events/origin_events_machine_age.txt:1203`）。
4. **一条采信 + 一条驳回**（S-15e）：引擎"官员自动补位"**采信**（连续 103 个月正证，硬边界假设被否证）；

   全是假阴性。落地必须改为**持续补位**。
5. **口径订正**：BACKLOG V-9 行「超限 → **维护涨** + 经验慢」**成立**——本机 `defines` 只硬编码了经验项
   （`LEADER_CAPACITY_XP_SCALE`），维护项在 exe 内，**不能据"本机零命中"否证它**（本次差点误判，已订正）。

## §4 规格（R0–R3）

### R0 —— 按职业独立定编（核心，必做）

- **目标量定义**：该职业**领袖总数**（含元首 / 继承人）≤ **目标常数**；**envoy 不计**。
- **目标常数取 3**（= `@base_leader_cap`）。理由：cap **不可读**（§7），只能取常数；
  原版同法先例 —— `num_owned_leaders < 2`（`origin_events_machine_age.txt:1203`）、
  文档示例 `num_owned_leaders < 8`。**这是"认定值常数"，与 D-49 的"把不可读值放进比较式"性质不同，属合法。**
- **禁止**：`count_owned_leader < leader_capacity` 之类（右值读不到 ⇒ 恒假/恒真）。
- **必须三类各一道**（commander / scientist / official）；**不得只做 commander**。

### R1 —— 剪枝目标选择（保守顺序）

- 仅当**该职业总数 > 目标**时才剪；一次剪到"总数 = 目标"为止。
- 剪**最后招募**者优先（`recruitment_date` 最晚），等价可判实现：`is_idle = yes` 优先。
- **硬豁免（一个都不能剪）**：`is_ruler` / `is_heir` / `is_councilor` / **在岗**（非 idle）。
- **豁免（剪了纯亏）**：带 paragon 特征 或 `leader_trait_eager` 且 `level < 4` —— 这些**不计入 cap**。
- **留痕**：`kill_leader = { show_notification = no }` 沿用既有形态（原版 `gray_goo_effects.txt:946`），
  并在注释中写明"**语义代偿：脚本层用 kill 代解雇**"。

### R2 —— 招募节流（上游，防复发）

- 创建前判："该职业总数 ≥ 目标 ⇒ 不创建"。
- ⚠️ **陷阱**：`num_owned_leaders` 是**全职业合计、含元首**，**不能**用于单职业判定；
  单职业计数**只能**用 `count_owned_leader` + `limit = { leader_class = X }`。
- 与 R1 的关系：R2 是**防新增**，R1 是**清存量**；两者**口径必须同为"该类总数"**（否则又会出现缺陷 A）。

### R3 —— S-15e 改写为持续补位

- 每月：若"内阁中无 official 在任"⇒ 创建 1 名。
- ⚠️ **去掉"一次性旗"必须补"防重复创建"的替代约束**：否则「无内阁官员」这一条件在**创建当月的同一次
  求值之后不会立即变真**（引擎入阁可能有延迟 ⇒ 会连开多名 ⇒ **自造超容**）。
  ⇒ **R3 的风险点必须先在实现前给出方案**（候选：月度冷却计数 / 以"本类总数 < 目标"作为创建前置门，
  即直接复用 R2 的节流；**推荐后者** —— 与 R0/R2 口径统一，不引入新状态）。

### 【明确不做】

- **不为统计领袖建游戏内账本**（铁律 20；现有实现的"零账本"方向正确，保留）。
- **不猜 cap 真值**（不可读）；不试图"读取并比较"。
- **不为了数量好看而剪豁免项**（paragon / Eager<4）。
- **不在 D-51 未修前先做"扩编"**（当前是缺矿物、缺消费出口，扩编只会放大支出）。
